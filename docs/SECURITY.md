# SunTrack — Security Architecture & Hardening Specification

This document details the comprehensive security controls, authorization hierarchies, audit logging mechanisms, and threat mitigation strategies implemented in SunTrack Enterprise.

---

## 1. Role-Based Access Control (RBAC) Hierarchy

SunTrack implements granular Role-Based Access Control using `spatie/laravel-permission`. User authorization is evaluated at the route middleware level (`role:Super Admin|Brand Manager`) and within Controller policy checks.

### Seeded Enterprise Roles & Permissions:
1.  **`Super Admin`**:
    - **Permissions:** Full system access (`*`). Can manage user accounts, assign roles, update system settings, revoke secure links, and perform system database backups.
2.  **`Brand Manager`**:
    - **Permissions:** Can create, read, update, and submit promotional campaigns and product promotions (`campaign.*`, `promotion.*`, `product.*`, `variant.*`). Can generate secure collaboration links and participate in 2-way comments. Cannot access system settings or user management.
3.  **`Finance Auditor`**:
    - **Permissions:** Read-only access across all promotional campaigns, historical pricing snapshots, margin protection analytics, approval histories, and activity audit trails (`campaign.view`, `promotion.view`, `report.export`, `audit.view`). Cannot modify business data.
4.  **`Operational Staff`**:
    - **Permissions:** Day-to-day operational execution. Can view and update assigned promotions and catalog products, but cannot approve/reject promotions or modify master pricing floors.

## 2. Authentication & Session Security

- **API Token & Session Authentication:** Powered by Laravel Sanctum (`auth:sanctum`). Admin users authenticate via login credentials, generating secure HTTP-only, SameSite-Lax session cookies or bearer API tokens.
- **Login Auditing (`login_histories` table):** Every authentication attempt (success or failure) is recorded immutably via `LoginHistory::create()`. Captured attributes include:
  - `user_id` (UUID foreign key, nullable on failed attempts)
  - `ip_address` (Client IP IPv4/IPv6)
  - `user_agent` (Browser/Device fingerprint)
  - `login_at` (ISO 8601 timestamp)
  - `status` (`successful` or `failed`)

## 3. Global HTTP Security Headers (`SecurityHeadersMiddleware`)

All HTTP responses generated by SunTrack pass through `App\Http\Middleware\SecurityHeadersMiddleware`, injecting strict enterprise security headers:
- `X-Frame-Options: SAMEORIGIN` (Prevents Clickjacking attacks).
- `X-Content-Type-Options: nosniff` (Prevents MIME-sniffing vulnerabilities).
- `X-XSS-Protection: 1; mode=block` (Enforces browser Cross-Site Scripting filtering).
- `Referrer-Policy: strict-origin-when-cross-origin` (Protects sensitive URI tokens in referrer headers).
- `Content-Security-Policy: default-src 'self' 'unsafe-inline' 'unsafe-eval' data: blob: https:;` (Restricts untrusted asset execution while allowing Vue SPA runtime compilation).

## 4. Secure Public Collaboration Links (ADR-015)

External Brand reviewers collaborate with internal Admins without requiring user account creation or login passwords. Security is enforced through multi-layered link governance:
1.  **64-Character Random Cryptographic Token:** Generates a secure URL (`/public-review/{token}`) using `Str::random(64)`.
2.  **Strict Lifecycle Management:**
    - **Expiration Monitoring:** Links enforce an optional `expires_at` timestamp. Once expired, access is blocked with HTTP `403 Forbidden` and an explicit expiration message.
    - **Admin Revocation:** Admins can instantly revoke compromised or completed links (`status = Revoked`).
3.  **Access Auditing:** Every view increments `view_count`, records `last_accessed_at`, and logs client IP and User Agent.
4.  **Reviewer Identification Governance:** External reviewers MUST submit their identity (Name, Position, Company, WhatsApp) before submitting approvals or rejections. This identity is cached in browser `localStorage` and embedded into `approval_histories` and `ActivityLogger`.

## 5. Threat Mitigation & Rate Limiting

To prevent brute-force attacks and Denial-of-Service (DoS) flooding, Laravel Throttle middleware is applied to critical endpoints:
- **Authentication Endpoints (`/api/v1/login`):** Throttled to `5 attempts per minute` per IP address.
- **Public Review Submission (`/api/v1/public/reviews/*`):** Throttled to `30 requests per minute` per token/IP to prevent automated review spamming.
- **Form Request Validation & SQL Injection Prevention:** All queries execute through Eloquent ORM parameterized PDO bindings. Strict validation rules in Form Requests prevent malformed payloads, XSS injection, and parameter tampering.
